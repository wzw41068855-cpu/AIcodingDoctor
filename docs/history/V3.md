# V3：一个 MCP 服务、Git worktree、受限 Docker pytest 和强制审计

V3 复用现有 `CodeSearchService`、`Editor/EditBatch`、状态模型和四节点修复图。旧 `graph.cli`、`run_demo_v2.py` 和只读 Agent 保持原用法；V3 不提供 Web、SSE、任务调度、持久化 Graph 或审批恢复。

## 模块和真实调用链

- `mcp_servers/`：四类工具分别为 `file_server.py`、`code_search_server.py`、`git_server.py`、`execution_server.py`，由 `server.py` 在一个 stdio 进程中注册，`context.py` 绑定同一任务依赖。
- `mcp_client/`：官方 MCP 2.3.0 客户端；一个 AnyIO 循环线程维护一个会话，原同步节点通过适配器调用远程工具。
- `workspace/`：干净提交、detached worktree、Git 命令安全配置及归属检查。
- `sandbox/`：唯一执行能力是固定 Docker pytest；没有 `run_command`、Shell、Ruff 或宿主 pytest 回退。
- `audit/`：独立于性能日志的强制 JSONL 审计。
- `v3_runtime/`：独立单任务 CLI，只通过可选 editor/runner 注入接入原图。

```text
V3 CLI → 审计 → 创建 worktree → Docker/本地镜像预检
       → 启动唯一 MCP 服务并绑定任务索引、Editor、DockerRunner
       → 原 RepairWorkflow
          Planner → MCP File/Search
          Coder   → MCP 快照/EditBatch/增量索引同步
          Tester  → MCP run_pytest → Docker
          Reviewer/Finalizer → MCP Git Diff/实际变更
       → 关闭 MCP → 最终审计 → 报告；默认保留 worktree
```

## 准备环境与镜像

使用项目已配置的 Python 环境安装 `requirements.txt`。只使用官方 MCP SDK，不引入 GitPython 或 Docker Python SDK。Git、Docker Desktop/Linux Engine 和本地 Linux 容器必须可用；远程 Docker 服务不在支持范围内。

用户可以提前显式构建教学镜像（此步可能联网下载 Python 和 pytest，不属于任务执行）：

```powershell
docker build -t aicd-pytest:local sandbox
```

构建上下文只包含 Dockerfile，不把仓库、`.env` 或宿主依赖复制进镜像。真实项目有其他测试依赖时，请自行提前准备相应镜像。任务只接受已有本地镜像，解析固定 image ID，并使用 `--pull=never`；不会在任务中执行安装脚本或根据模型需求改变镜像。

## 运行任务

源仓库必须可信、有至少一个提交、没有已跟踪修改或未跟踪文件。主目录中被忽略的文件不会复制到 worktree。不要自动提交用户修改；有修改时先自行整理源仓库。

```powershell
python -m v3_runtime.cli --repository C:\work\myproject --trusted-copy --request "修复 calculator.py 的 add 加法" --allow-write calculator.py --tests tests/test_calculator.py --image aicd-pytest:local
```

凭据使用当前进程环境的 `DASHSCOPE_API_KEY`，不写入任务配置或容器。真实模式沿用项目模型和 V1 索引配置，会产生 API 用量。每任务索引独立，不复用用户现有 Chroma Collection。

对于已提交的 `calculator.py` 教学仓库，可增加 `--demo-model success`、`retry` 或 `limit`。这仅模拟 LLM/向量库；仍然创建真实 worktree、连接真实 stdio MCP 和执行真实 Docker pytest，不是本地测试替代模式。

可选 `--revision HEAD`、`--timeout 60`（每轮测试最多 300 秒）、`--max-iterations 3`（最多五轮）。修复仍只允许已有业务 `.py`，不能编辑测试、配置、依赖、创建文件或删除文件。可写文件范围由用户参数固定，Planner 不得扩大。

## 容器边界

执行器复制 worktree 中受跟踪的普通非敏感文件，忽略隐藏路径，不复制 `.git`、`.env`、凭据、链接或宿主环境。任务启动前拒绝已跟踪环境凭据、符号链接和子模块。输入最多 1000 个文件、64 MiB；不自动下载 LFS 对象。含隐藏运行配置或特殊布局的仓库需要先整理为适配的可信项目。

过滤快照只读挂载到 `/input`，再复制到容器内 `/workspace` 的临时文件系统，测试写入不会回传宿主。容器使用：

- 非 root UID/GID 65534、断网、只读根文件系统、全部 capabilities 移除、禁止提权。
- 1 CPU、1 GiB 内存且无额外 swap、128 PID、文件描述符限制、禁用 core dump。
- `/tmp` 64 MiB、`/workspace` 128 MiB，均有 noexec/nosuid/nodev 限制。
- 无 Docker socket、主目录或凭据挂载；固定 Python 入口和 pytest 参数。
- 输出只保留最多 16 KiB；持续排空防止管道死锁。JUnit tar 最多 4 MiB，只在内存读取普通 XML，拒绝实体声明，不解包宿主文件。

超时或 MCP 取消会通知等待线程停止 Docker CLI，再核对任务标签并移除实际容器；不能仅杀死 Docker CLI。清理结果无法确认时报告 blocked/环境异常，输出需要人工核对的容器名。宿主或 Docker 服务突然崩溃时无法保证自动回收，应按报告中的任务 ID 查找 `aicd.task` 标签容器。

MCP 会话关闭后，宿主还会先写恢复审计，再按完整任务标签检查残留容器并逐个核对归属后回收，覆盖服务子进程提前退出的情况。恢复审计或回收失败均阻塞任务，不会对其他任务执行全局清理。

这是面向可信仓库的受限容器执行，不是虚拟机级恶意代码隔离。测试结果仅证明可见测试，不提供隐藏测试验收。

## 审计、日志和结果保留

CLI 打印任务产物目录、worktree、固定提交 SHA、镜像 ID、`audit.jsonl`、`report.json` 和 Diff 路径。退出码保持 `0=success`、`1=failed`、`2=blocked`。

审计在副作用之前写入开始事件并 flush/fsync，失败则不执行业务；操作后审计失败报告 blocked，保留已修改文件，禁止继续调用或自动重试。每次工具包含独立调用 ID、时间和耗时；编辑额外记录文件路径和前后哈希。SDK 校验前还有请求级审计，因此非法参数和未知工具也可追踪。参数正文、Prompt、源码和异常正文不写入审计。完整 Diff 是独立审查产物，不塞进审计行。

MCP 服务是会话期间唯一审计写入者，父进程仅在会话前后写入；一个服务内工具调用串行。普通计时日志故障不等于审计故障，两者职责不同。stdio stdout 只用于协议，服务性能日志写 stderr；宿主计时可写入 `logs/v3_timing.log`。

默认保留 worktree、索引、日志和修复结果，不自动提交、合并、推送或回写源目录。`WorktreeManager.cleanup()` 仅接受具有匹配归属记录且没有任何修改的工作树；不提供自动丢弃功能。仅在人工审查并备份结果后，按 Git 正常 worktree 管理流程清理。

## 验证

```powershell
python -m pytest tests/v3 -q -rs
python -m pytest tests -q -rs
```

离线测试覆盖真实临时 Git 仓库、worktree、官方 MCP 内存传输和真实 stdio 子进程；模型、Embedding 和容器结果使用明确替身，不访问 API、不清空真实索引。

已准备镜像后，显式启用真正的 Docker + stdio MCP 修复集成测试：

```powershell
$env:AICD_V3_TEST_IMAGE = "aicd-pytest:local"
python -m pytest tests/v3/test_docker.py -q -rs
```

镜像未配置时该集成项跳过，不能据此宣称完整 Docker 闭环验收通过。Windows 无符号链接权限时，相应旧测试也会跳过；每次交付以实际报告为准。

还可设置 `AICD_V3_SECURITY_IMAGE` 为已有、无额外数据卷的 Linux 镜像，运行 `test_real_docker_security_configuration`。该测试只创建容器、检查实际的限制和只读挂载，然后按任务标签移除；不启动镜像应用，因此不能代替真实 pytest 闭环验收。
